🔐 Security Policy

Sassy Software Design House Pty. Ltd.

Security, privacy, integrity, and responsible development are fundamental principles of Sassy Software Design House.

We are committed to developing, maintaining, and improving our software responsibly. We appreciate the assistance of users, developers, researchers, and contributors in identifying potential security vulnerabilities.

1. Supported Versions

Security updates are prioritised for actively maintained and supported versions of our projects.

Version| Security Support
Current stable release| Supported
Previous release| Supported where feasible
Experimental / Beta releases| Limited support
Archived / Discontinued versions| No guaranteed security support

Support status may vary between individual projects.

2. Reporting Security Vulnerabilities

If you discover a potential security vulnerability, please report it privately to the project maintainer.

Please do not disclose vulnerabilities through:

- Public GitHub Issues
- Public Pull Requests
- Public Discussions
- Social media or other public platforms before responsible disclosure

Reports should include, where possible:

- Project name and affected version
- Description of the vulnerability
- Potential impact
- Steps required to reproduce the issue
- Relevant logs, screenshots, or proof of concept
- Suggested mitigation, if known

Please avoid submitting sensitive personal information or real user data.

3. Responsible Disclosure

We request that security researchers:

- Act in good faith.
- Avoid accessing, modifying, deleting, or exposing other users' data.
- Avoid disrupting services or systems.
- Do not exploit vulnerabilities beyond what is reasonably necessary to verify the issue.
- Allow the maintainer reasonable time to investigate and address the vulnerability before public disclosure.

Sassy Software Design House reserves the right to determine the appropriate remediation and disclosure timeline based on the severity and circumstances of the report.

4. Response and Remediation

We aim to:

- Acknowledge security reports within 5 business days.
- Assess reported vulnerabilities as soon as reasonably possible.
- Provide updates during the investigation where appropriate.
- Release patches or mitigation guidance when feasible.
- Notify affected users when a significant vulnerability requires their attention.

These are target response times, not guaranteed service-level commitments.

5. User Responsibilities

Users are encouraged to:

- Use supported and updated software versions.
- Keep dependencies updated.
- Protect passwords, API keys, tokens, and credentials.
- Avoid sharing sensitive information in public repositories.
- Review project documentation before deployment.
- Report suspected security issues responsibly.

6. Contributions and Code Integrity

Contributions may be reviewed for security, functionality, quality, and compatibility before acceptance.

Maintainers may reject contributions that introduce malicious code, insecure functionality, unauthorised access mechanisms, or other unacceptable security risks.

7. Scope and Limitations

This policy applies to security concerns involving Sassy Software Design House projects and their associated repositories.

This policy does not constitute a bug bounty programme. Financial rewards are not guaranteed.

8. Contact

Security reports should be submitted through GitHub's private vulnerability reporting feature where available.

For general security questions, please use the official contact channels published by Sassy Software Design House Pty. Ltd.
